# 诊录助手 · 实时会诊与复诊模块

医生在本次会诊中核对原话、决定是否补问，并在复诊时接续上次留下的事项。首版以本机单用户工作台为交付环境，前端通过 HTTP 和 SSE 接入。模型建议、医生对事项的处理和医生确认的病历分别留存。

## 完整功能规划

| 模块 | 医生或教师可以做什么 | 交付阶段 |
| --- | --- | --- |
| 本次会诊 | 阅读逐句转录，定位原文与可用音频；查看带依据的补问、核对和重要线索；查询当前会话，审核五字段草稿 | 复用现有后端，首版增加持久化事项 |
| 同一患者复诊 | 选择患者档案，读取上次确认病历与跨次待办；结合本次原话核实历史用药、过敏及描述变化 | 首版 |
| 多人会诊与纵向病史 | 纠正发言人与病史归属，按时间整理多次就诊的变化、不同医生的意见、已达成共识及负责人 | 后续 |
| 相似病例 | 在获授权的去标识化病例中检索，展示相似点、关键差异、实际诊疗过程与已知随访结局。由医生主动调阅 | 后续 |
| 教师复盘 | 按当时可见的信息回看建议与依据，创建专题病例集，批注重复提醒、证据不足、遗漏和错误归属 | 后续 |

## 功能如何参与一次问诊

| 场景 | 触发与输出 | 医生或教师的决定 |
| --- | --- | --- |
| 患者叙述病情 | 按句保存发言、时间与原文 ID。暂时性的识别结果不触发分析。助手根据已有上下文返回值得问的问题，可返回空建议 | 查看原句或在时间可靠时回听。医生的问题和患者的肯定回答分别处理 |
| 患者更正或描述矛盾 | 比较主体、时间、否定和不确定性。两句话可同时展示，历史冲突另列旧病历版本 | 确认是时间变化、说话对象不同、识别问题，还是真有矛盾 |
| 医生已追问 | 提示绑定一个持续事项。首版由医生标记已问、登记结果或选择下次随访 | 保留“已问待答”“患者不详”“明确否认”的区别，答案用结果文本记录 |
| 需要查找信息 | 当前会话问答依据原文回答；按需查看补问、鉴别、检查目的及治疗方向中的依据和缺失条件 | 是否采纳由医生决定。指南检索留待与可核验的资料库接入 |
| 多位医生共同讨论 | 后续从带身份的发言中整理提出人、不同意见、已确认共识、待办、负责人及完成记录 | 提出建议、形成决定和实际执行分别确认 |
| 复诊及长期随访 | 首版逐项返回上次与本次病历字段及原文。后续将多次确认记录中的发作时间、检查及用药变化组织成时间线，支持跨次问答 | 医生判断文本差异的临床含义，可核实上次待办是否完成 |
| 参考其他患者病例 | 后续由医生按症状组合、病程、检查等条件主动检索获授权和去标识的病例，展示相同点、关键差异及结局是否已知 | 参考病例独立展示。其诊断或处置不直接进入当前患者记录 |
| 教学复盘 | 后续支持按时点还原当时已知原文、提示、处置和之后的更正。可建立专题病例集，教师批注绑定原句、建议与版本 | 比较不同问法，分别统计重复打扰、建议有用性、遗漏及归属错误。教师批注独立于病历 |

## 首版业务流程

1. 医生建档或选定已有患者。患者编号标识身份，同名患者分别保存。旧会话仍可单独使用，确认归属后才关联患者。
2. 新问诊打开时返回最近一次已确认的既往病历和待随访事项。历史事实注明来源就诊、确认版本及日期；患者首诊返回相同结构的空结果。
3. 确定的本次转录按批落库。后台读取当前原文、可引用的历史字段与已有事项，合并连续输入后分析。历史中曾用某药只构成本次核对线索。
4. 每条当前建议引用本次原句。引用上次病历时另外返回历史字段及出处。转录版本落后的结果进入历史。病历生成继续使用原有本次转录输入。
5. 补问与核对使用跨分析轮次稳定的事项 ID。医生可以标记已问、已解决、已忽略，或登记下次随访。患者答不上来可以记录为“不详”。普通诊疗思路另行展示供医生判断。
6. 会诊结束后医生确认病历。下次复诊只带入明确选择随访且仍未结的事项，保留最初提出和后来处理它的会话。

## 数据、边界与一致性

- 患者档案、会话、确认快照、实时分析轮次、可处理事项和事项操作记录分别有稳定标识。单次分析产生的建议 ID 用于追溯模型输出，事项 ID 用于医生操作和跨次追踪。
- 同一患者的已确认记录才可作为历史依据。历史记录取本次会话创建时已完成的最近一次就诊。姓名、自由填写的旧编号和相似描述均不触发自动归并。
- 事项状态为待核实、已问待答、已解决、已忽略。是否下次随访单独保存。医生操作记录处理人、时间、版本与结果。已处理事项优先于迟到的模型返回，网络重试不得制造第二个事项。
- 原文来源必须属于本次转录，历史依据必须属于允许引用的既往快照。重要线索需要原文支持，助手允许返回空结果。诊疗思路与医生确认事实分别呈现。
- 读取摘要、保存事项和记录确认独立于模型可用性。页面首次读取和 SSE 重连可取得完整状态。当前处理人是本机填报的标识；机构账户、权限和审计将在机构部署阶段接入。

## 前端接入顺序

| 操作 | 接口（相对于 /api） |
| --- | --- |
| 建档、搜索 | POST /patients，GET /patients?query= |
| 选定患者新建问诊 | POST /sessions，传 patient_id |
| 明确关联未绑定的旧会话 | PUT /sessions/{id}/patient |
| 读取既往确认记录与待办 | GET /sessions/{id}/follow-up-summary |
| 列出、手动添加、处理事项 | GET 或 POST /sessions/{id}/items，PATCH /sessions/{id}/items/{item_id} |
| 助手状态与推送 | GET /sessions/{id}/assistant/advice，GET /sessions/{id}/live/events |
| 首屏或轮询同步 | GET /sessions/{id}/live/snapshot，返回与 SSE 相同的完整快照 |

## 首版验收

- 同名不同患者之间隔离。旧会话可读取；初诊无历史；草稿及晚于本次开始的确认记录不会出现在复诊摘要。
- 历史用药与本次说法不同，两种依据可分别打开；越界引用被拒绝；旧用药不会自动写成本次事实。
- 医生处理后刷新、重连、模型改写同一问题或迟到返回，处理结果仍保留。新增操作与重试可区分，并发修改可检测冲突。
- 复诊能处理上次的随访事项，保留来源及操作轨迹。模型失败时仍可读摘要和保存事项。
- 联调以虚构数据覆盖初诊、复诊、冲突与断线重连。真实服务评测另行记录延迟、费用、重复提醒和错误归属。

具体请求体、状态值、错误码和四组联调样例见[接口契约第 8 节](api.md#follow-up-api)。
